## 概要
- html + インラインjsによる1ファイルツール
- 外部ライブラリ、cssに依存しない
- CLIのGUI化したような設計思想で、ツールはシンプルな入出力と1つの役割を持つ

## 想定利用環境
以下のような、まともな既存システムも無え！　新規開発も無え！　まともな認可済みソフトも無え！
そんな都会の僻地、オフィスの荒野でサバイバルする人々のためのツール

### まともな既存システムも無え！
- 不連続なシステム
  - システム化されているが、システム同士が繋がっておらず、手作業の変換・目視確認が必要
  - システムを管理する部署にメールや別システム経由のデータ追加・更新の依頼が来る……ExcelやWordで
  - スニーカーネット
- 貧弱なチェックシステム
  - システムはあるが、バリデーションが貧弱でどんなデータも受け入れるが、誤ったデータは機能しないか障害を引き起こす
  - プレビューできない
- レガシーシステム
  - 何が駄目なのか、いざ言葉にしようとすると難しいが、設計思想が古すぎるせいで、大体全てが駄目な直すより作り直すほうが速そうなシステム
- 生データの利用
  - CLIやAWSのDynamoDB、SQLなどの、剥き出しのシステムを直接の扱う必要があり、使いづらい生データの処理が必要
  - 個人情報やシステム構成のような機密情報を含み得るため、馬の骨の無料変換サイトが使えない

### 開発も無え！
- 既存システムがパッケージのため改修不可、または余力、政政治的な理由など何らかの理由により改修できない
- 費用、政治的或いは何らかの理由により新規システムを満足に開発する事ができない
- サーバーも建てる事ができない

### まともな認可済みソフトも無え！
- インストールできるのはMSオフィスとサクラエディタ、WinMergeのみ
- Python、Node、その他追加が必要なランタイムは一切無し
- SDK？　なにそれおいしいの？

### 木こりはいるが、金物屋はいねえ！
- 木こりも大工もいるが、木を切り、新しいシステムを建てるのに忙しすぎて、ボロボロの刃を砥ぐ暇も、砥ぐ為に金物屋を雇うお金もない

### おらこんな環境いやだ
- シリコンバレーに出だなら、USBにデータ貯めで、専用端末まで持っていくだ


## 構成要素
### ツールボックス
- CLIにおけるコマンドを解決して実行するシェルに相当
- 役割
  - 1つ以上のツールの実装またはリンクを持つ
  - ナビゲーションの提供
    - 使えるツールの一覧化
    - 類似のツールのグループ化
    - 素早く使い分けできるようにする
  - 表示領域の提供
    - ツールが表示される領域をiframeで提供する
  - スコープの分離
    - ツール同士の定義や副作用が衝突しないようスコープを分離し、ライフサイクルを制御する
- 設計
  - ナビゲーション
    - ナビゲーションメニュー
      - ビルド時にツールリスト定義から作成
    - 表示領域
      - iframe
      - インラインツール
        - ツールボックス自身をiframeのsrcに指定
        - 対象のツールをiframeのsrcにアンカーとして指定
        - window.parentを持つ場合、アンカーを読み取り、
          - 対象のツールのDOMを主領域に挿入する（iframeは生成しない）
          - 対象のツールのコードを実行する
      - 外部ツール
        - ツールのsrcの指定のみ
      - コンビネーションツール
        - あるツールのツール定義に配列が設定されている場合、コンビネーションツールとして扱い、要素の数だけiframeを生成し、ツールをロードする
        - コンビネーションツールは非コンビネーションツールの一般化で、非コンビネーションツールは配列サイズ1のコンビネーションツールである特殊値として扱う
- 特殊な構成
  - スイスアーミーナイフ（インラインツールボックス）
    - ナビゲーション対象のツールが全てインラインツールであり、1ファイルで完結するもの
    - 社内配布などに便利
- ビルド
  - INPUT
    - テンプレートのhtml
    - css
    - ツール定義（識別子、名称、タイプ、パス）
    - ナビゲーション定義（ツリー構造、ラベル、ツールの識別子）
  - ナビゲーション定義からナビゲーションDOMの生成
  - インラインツール
    - ツール定義のパスのディレクトリにあるhtml及びcssを文字列化し、ツール定義定数に追加する
    - ツール定義のパスのディレクトリにあるjsを、丸ごと () => {} で囲んで関数化し、scriptタグ内でツール定義変数に追加する
  - 外部ツール
    - 識別子、名称、パスをツール定数定数に追加する
    - パスは実行時のパスとして扱われる
  

### ツール
- CLIにおけるシェルから実行される1つのコマンドに相当
- インラインツール
  - ツールボックス内にインラインとして格納するビルド方式
  - 十徳ナイフ（スイスアーミーナイフ）の一本のツール。スタイルと汎用処理は共通化できるが、ツールボックス（柄）が無いと使えない
  - 長所
    - これのみを持つツールボックス（スイスアーミーナイフ）は1ファイルになるため配布しやすい
  - 短所
    - ツールボックスごとビルドし直す必要があるためメンテナンスが面倒
- 外部ツール
  - 外部ツールとして独立させるビルド方式
  - 道具箱に入った道具類
  - html+インラインjsのため単体使用できるが、数が増えやすいためツールボックスによる整理とナビゲーションがある方が使いやすい
  - ツールの数だけファイルができるため、個人利用やファイルサーバーに配置し、移動させない利用に向く
  - 長所
    - ツールボックス無しでも単体で利用できる
    - ツールを個別に更新できるためメンテナンスが容易
    - ツールボックスのナビゲーションの追加・修整も容易
  - 短所
    - リテラシーが低いと箱を本体と勘違いし、ツールボックスのみ移動・コピーして使えなない空箱を作ってしまう
